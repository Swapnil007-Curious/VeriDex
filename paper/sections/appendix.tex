\section{Error-analysis procedure}
\label{app:errors}
\input{tables/errors}
A failure is a G4 test question that is answerable and was answered incorrectly or withheld, or unanswerable and was answered.
Pre-labels were computed in this order: \emph{retrieval miss} when no passage in the final context is relevant to any gold provision; \emph{chunk boundary} when only some gold provisions are covered; \emph{verifier false reject} when the system abstained after a guard failure or the critic and G2's identical first-round answer was judged correct; \emph{verifier false accept} when a released answer contains a sentence the NLI judge marks unsupported; otherwise \emph{synthesis error}.
Each item was then read, with AI assistance, and its category kept or changed; \emph{evaluation artefact} (a correct answer the judge rejects, a wrong gold answer, or an ambiguous question) can only be assigned by reading.
The categories are exclusive (one per failure), so the two consumer-law synthesis errors that the critic accepted are not counted as verifier false accepts. Two examples:

\section{Reproducibility}
\label{app:repro}
All experiments ran on one laptop: \V{hw.cpu} (\V{hw.cores} cores, \V{hw.threads} threads), \V{hw.ram}\,GB of RAM as reported by the operating system, no GPU, Windows~11 (reported by Python as ``\V{hw.os}''), Python \V{hw.python}, PyTorch \V{hw.torch}, sentence-transformers \V{hw.st}.
The result metadata record the commits of the test runs: consumer-law retrieval \cmd{\V{repro.cl.ret}}, consumer-law generation \cmd{\V{repro.cl.gen}}, CS/AI retrieval \cmd{\V{repro.cs.ret}}, CS/AI generation \cmd{\V{repro.cs.gen}} and the hosted ablations \cmd{\V{repro.cl.g2h}} (consumer law) and \cmd{\V{repro.cs.g2h}} (CS/AI), both resumed from cached calls across sessions (Table~\ref{tab:access}); in each case the metadata record that the working tree had uncommitted changes, whose diffs were not saved.
The tables and figures of this paper were generated at commit \cmd{\V{repro.head}}.
LLM responses, rerank scores and NLI scores are cached on disk, so rerunning an evaluation with the caches reproduces its outputs. The per-question records and the caches are not in the public repository; the statistics derived from them are snapshotted in \cmd{paper/data/}.
